移籍の扱い
別リーグにまたがる年度は球団ごとに別行とし、年度・月別・詳細指標を同じ区分で集計する。
同一リーグ内の移籍は年度内で合算し、日付が最新の出場球団に所属させる。
試合別データには実際に出場した当時の球団を残す。
sourceTeams は元の所属履歴、teams/team は年度画面の表示・絞り込み用。
移籍先未出場の場合は出場履歴だけで新所属を特定できないため、公式所属情報の追加が必要。
2026年の公式公示で確認したトレードはすべて別リーグ間。
https://npb.jp/announcement/2026/pn_traded.html

再実行（リポジトリ直下から）
python -m pip install -r scripts/dashboard_requirements.txt
python scripts/audit_dashboard.py
python scripts/collect_final_games.py
python scripts/rebuild_annual_totals.py --pitcher-manifest-only
python scripts/refresh_dashboard_stats.py
スポーツナビ障害時: python scripts/refresh_dashboard_stats.py --source npb
python scripts/rebuild_annual_totals.py --refresh-manifests
python scripts/test_transfer_aggregation.py
node scripts/test_transfer_selection.js
python scripts/verify_annual_totals.py
python scripts/verify_final_games.py

scripts/collect_final_games.py は追加2試合の一球速報を各ページ1回取得し全投手で再利用。成績・コンテキスト・wOBAイベントも更新する。
全季NPBイベントを保存済みの場合は、部分的なスポーツナビイベントでwOBAデータを上書きしない。
使用したスキルの解析・描画コードも scripts/build_dashboard.py に同梱し、個人のスキル配置への依存をなくした。
scripts/rebuild_annual_totals.py は公開済みmanifestから集計し、元CSVがない過年度の集計を保持する。
--refresh-manifests は新しいgeneratedデータを発見し、投手manifest・表示用詳細JSONも更新する。
--repair-details-only は不足する表示用詳細JSONのみを元の投球JSONから再生成する。
--batter-only は投手成績と球場係数を保持し、打撃年度・月別指標のみ更新する。敬遠コンテキストも補正した場合は通常の全再集計を使う。
summary/build_manifest.py も元データがない過年度の集計を保持する。

公式ページのURL対応表はaudit_dashboard.py、選手ID対応は公式打撃キャッシュとNPB名簿から作る。
refresh_woba_season.py は失敗時に保存済みHTMLから再開し、全試合の照合に成功するまで公開JSONを更新しない。
--game-id、--audit-only、--audit-cached は部分検証専用で、公開データを上書きしない。
既存の sportsnavi_woba_events_2026.json という名前を維持するが、source/eventParserにNPB公式由来と記録する。
検証スクリプトの過年度・計数保持確認は、実行時のHEADとの比較で行う。

取得済み成績キャッシュは summary/game_batting_cache.json と summary/game_decisions_cache.json。
NPB代替取得時はキャッシュの sources に取得元を記録する。
.site-build 内のHTML・対応表・エラーログは一時ファイルであり、必要時は照合スクリプトから再作成できる。
公開前に python scripts/build_github_pages.py で成果物を検証し、対象ファイルをcommitしてmainへpushする。
build_github_pages.py は .site-build をビルド用に初期化するため、取得・集計・検証を完了してから実行する。
